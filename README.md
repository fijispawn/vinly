# Винный турнир

Веб-игра для очной слепой дегустации по [техническому заданию](wine-brackets-spec.md). Интерфейс написан на React и Next.js (App Router). До финала игрокам и общему экрану сервер выдаёт только номера бутылок.

## Запуск через Docker Compose

    docker compose up --build -d

Откройте http://localhost:3000. Для телефонов в одной сети откройте IP компьютера на порту 3000.

    docker compose ps
    docker compose logs -f
    docker compose down

Данные аккаунтов, игр и дневников лежат в Docker-томе `wine-app_wine_data` и сохраняются после `docker compose down` или пересборки. Команда `docker compose down -v` удалит этот том и все данные.

Игрок и ведущий создают аккаунт по логину и паролю. Пароли хранятся в виде хэша scrypt с индивидуальной солью. Смена пароля доступна в профиле. Почтовый сервис для входа не нужен.

Учебные аккаунты по умолчанию отключены. Для их создания задайте `SEED_DEMO=1` и четыре собственных пароля длиной от 10 символов: `DEMO_HOST_PASSWORD`, `DEMO_ANNA_PASSWORD`, `DEMO_MAX_PASSWORD` и `DEMO_CATALOG_PASSWORD`. Эти переменные передаются через `compose.yaml`; не сохраняйте их в репозитории. Будут созданы аккаунты `demo-host@mail.ru`, `demo-anna@mail.ru`, `demo-max@mail.ru` и `test@mail.ru`. В личную коллекцию последнего добавятся два вина SimpleWine. Повторный запуск не создаёт дубликаты.

Учебные игры можно создать или восстановить командой:

    docker compose exec -T wine-app node --input-type=module < scripts/demo-game.mjs

Сценарий создаёт один завершённый турнир и один турнир, ожидающий открытия первой пары. При повторном запуске он не создаёт игры с теми же названиями ещё раз. В учебной игре ведущий открывает пару и закрывает голосование, а оба игрока выставляют оценки и выбирают победителя. После последней пары ведущий раскрывает бутылки; только тогда карточки вин появляются в дневниках игроков.

## Запуск без Docker

Требуется Node.js 22 или новее.

    npm ci
    npm run dev

Для запуска в режиме production:

    npm run build
    npm start

Откройте http://localhost:3000. Данные сохраняются в `data/state.json`. Переменные `PORT` и `DATA_DIR` позволяют изменить порт и путь к данным. Для выбора другого порта передайте `-p`, например `npm start -- -p 3100`.

## Возможности

- Лобби с кодом и QR-приглашением, роли ведущего, игрока и общего экрана.
- Импорт карточки вина по URL с ручной проверкой и правкой. Для SimpleWine есть запасной текстовый способ чтения. Если магазин и текстовый сервис блокируют сервер, ведущий может открыть карточку в браузере, скопировать её содержимое целиком и вставить в форму: приложение заполнит поля из текста. Черновик из URL остаётся последним запасным вариантом.
- Турнирная сетка для 2–16 бутылок, оценки четырёх характеристик, отдельный голос за проход, пропуск пары и повторный тайный выбор при ничьей.
- Скрытие карточек до финала на уровне API, раскрытие, номинации и личный дневник с историей дегустаций.
- Личная коллекция вин: добавление по ссылке или вручную без турнира, редактирование карточек и заметок.
- Сохранение ответов и состояния игры между перезагрузками. Клиенты получают изменения с сервера каждые 2,5 секунды.

## Проверка

    npm test
    python3 test/integration.py

Интеграционный тест запускает отдельный сервер с временным хранилищем и требует локальных подключений к `localhost`.

## Развёртывание

Контейнер рассчитан на один серверный процесс: хранилище представляет собой один JSON-файл. Для нескольких экземпляров приложения понадобится транзакционная база данных. При публикации в интернете поставьте перед приложением HTTPS-прокси. Импорт вина и QR-код требуют доступа к внешним сервисам; если импорт недоступен, карточку можно заполнить вручную.

### Production на 194.67.106.162

Приложение развёрнуто отдельно от прочих проектов в `/opt/wine-brackets` через `deploy/compose.prod.yaml`. Контейнер слушает только `127.0.0.1:3100`; Nginx публикует `https://194.67.106.162:8443/`. HTTP на IP перенаправляется туда. Production-конфигурация не включает `SEED_DEMO`, поэтому известных тестовых логинов нет.

Постоянные данные находятся в Docker-томе `wine-brackets_wine_data` (`/app/data/state.json` внутри контейнера). Пока приложение работает в одном экземпляре, отдельная СУБД не нужна. Не запускайте одновременно второй экземпляр с этим томом: файл состояния рассчитан на один процесс.

Обновление: скопировать новые файлы в `/opt/wine-brackets` без удаления существующих, затем выполнить `docker compose -f /opt/wine-brackets/deploy/compose.prod.yaml up --build -d --no-deps app`. Перед обновлением с пользовательскими данными сделайте копию тома. Не используйте `docker compose down -v` или `docker volume rm`: они удалят данные приложения.

Домен приложения: `https://vinly.fun/`. `www.vinly.fun` и HTTP перенаправляются на него. DNS-записи `A` для `@` и `www` у Рег.ру указывают на `194.67.106.162`. Отдельные Nginx-конфигурации домена: `/etc/nginx/sites-available/vinly.fun-http` и `vinly.fun-https`; исходники находятся в `deploy/nginx-domain-http.conf` и `deploy/nginx-domain-https.conf`. Сертификат `/etc/letsencrypt/live/vinly.fun` выпущен через webroot `/opt/wine-brackets/acme-webroot`. Штатный `certbot.timer` продлевает его, а сохранённый в renewal-конфигурации `renew_hook` проверяет и перечитывает Nginx. Пробное продление прошло успешно.

Прежний доступ по IP `https://194.67.106.162:8443/` сохранён. Его сертификат хранится отдельно в `/opt/wine-brackets/certbot/config` и обновляется таймером `wine-brackets-cert.timer`. Nginx-конфигурации IP: `/etc/nginx/sites-available/wine-brackets-http` и `wine-brackets-https`. Контейнер и том данных при подключении домена не менялись.
